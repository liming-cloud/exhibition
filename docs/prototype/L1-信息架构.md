# L1 信息架构稿（Issue #2）

本稿只确认**放什么、按什么顺序**，不涉及视觉。确认后进入 L2 首页高保真（Issue #3）。
参考站：https://www.maifexpo.com/ 。文中 `[Q1]` 这类编号是需要你拍板的点，回复时按编号说即可。

## 0. 怎么看原型

```bash
cd exhibition-webside
NUXT_PUBLIC_MOCK=1 pnpm dev          # 不需要启动后端，所有 /api 返回 server/mock/data.ts 里的模拟数据
# 浏览器打开 http://localhost:3000/?theme=orange 或 ?theme=blue，选择会记住，站内跳转保持同一配色
```

- Mock 数据按真实运营规模准备：35 场展会（6 大洲 25 国，含已结束的和超长展会名）、15 篇资讯、9 个案例、6 条补贴、4 位顾问，用来检查分页、截断、空状态。
- 图片是带"示意图"字样的深色占位图，正式图片由后台上传；L2 高保真前需要你提供 Logo 和 3 张 Banner 素材，见第 5 节。

## 3. 内页模块清单

### 3.1 展会目录 `/exhibitions`
```
页头：标题 + 面包屑
大洲 tab：全部 | 亚洲 | 欧洲 | 北美洲 | 南美洲 | 非洲 | 大洋洲
筛选：国家（随大洲联动）· 行业（能源/电梯/医疗）· 年份 · 关键词 · 「只看即将开始」
列表：展会卡（名称最多 2 行截断 · 时间 · 国家城市 · 行业标签 · 状态：即将开始/已结束 · 「主推」角标 · 报名按钮）
分页；筛选条件同步到地址栏（可分享、可返回）；无结果时显示空状态 + 「联系顾问帮你找」
```
### 3.2 展会详情 `/exhibitions/:id`
```
页头：展会名 · 时间 · 地点 · 行业 · 状态
主体：左侧正文（简介/展品范围/参展服务）· 右侧常驻卡片（报名按钮 + 顾问电话 + 补贴提示）
底部：同国家或同行业的相关展会 4 条
已结束的展会：报名按钮改为「预约下一届」
```
### 3.3 参展服务 `/services`（新增）
```
服务项目 6 项（图标 + 说明）→ 服务流程 5 步（咨询 → 选展 → 报名 → 筹备 → 参展与跟进）→ 补贴政策入口 → 咨询转化条
```
- `[Q6]` 服务项目文案和流程步骤：我先按上面 6 项 / 5 步写占位，你提供真实文案后替换。是否需要在后台可配置？**推荐先写在前端**，变动少，后台配置以后再加。

### 3.4 补贴政策 `/subsidies`、`/subsidies/:id`
列表（标题 · 补贴金额 · 申报时间段 · 状态：申报中/已截止）→ 详情（正文 + 「咨询申报」按钮）。

### 3.5 行业资讯 `/news`、`/news/:id`
列表（封面 · 标题 · 摘要 2 行 · 日期，分页）→ 详情（正文 + 上一篇/下一篇 + 相关展会推荐）。

### 3.6 成功案例 `/cases`、`/cases/:id`
列表（封面 · 标题 · 摘要，3 列卡片，分页）→ 详情（正文 + 咨询转化条）。

### 3.7 关于我们 `/about`
公司简介（后台可改）→ 核心优势 3～4 项 → 展团风采照片墙 → 合作展会 Logo 墙 `[Q7]`。不再重复联系方式，底部放咨询转化条。

### 3.8 联系我们 `/contact`
顾问卡片（姓名 · 负责区域 · 电话 · 微信，后台维护多位）→ 公司地址 / 邮箱 / 工作时间 → 留言表单（复用报名表单） → 地图位置 `[Q8]`。

- `[Q7]` 合作展会 Logo 墙需要各展会 Logo 授权和图片，没有就先不做。
- `[Q8]` 联系页地图用静态图片（推荐，不依赖第三方 Key）还是高德地图嵌入？

## 4. 新增接口约定（mock 已实现，Issue #5 后端按此实现）

| 接口 | 返回 | 说明 |
|---|---|---|
| `GET /exhibition/featured` | `R<Exhibition[]>` | 后台勾选的主推展会，按 `sort` 排序 |
| `Exhibition` 新增字段 | `featured: boolean`、`coverUrl: string`、`summary: string` | 主推标记、封面图、一句话介绍 |
| `GET /contact/consultants` | `R<Consultant[]>` | `{ id, name, title, phone, wechat, sort }`，`title` 写负责区域 |
| 关于我们简介 | 沿用 `contact_info.company_profile` | 不新增表 |
